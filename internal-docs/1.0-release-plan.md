# 1.0 Release Plan

- Owner: repository maintainer
- Decision date: 2026-07-30
- Target stable date: **2026-08-17**
- Earliest stable date: 14 full days after the complete public RC becomes
  installable
- Canonical status source: this document

This plan replaces separate interpretations of the implementation-plan,
roadmap, native-audit, and release-handbook checklists. Those documents provide
detail; a requirement blocks 1.0 only when it appears below.

## Scope locked for 1.0

1. Node.js 22.13+ on the eight documented native platform targets.
2. The six public compatibility families and the existing native profiles.
3. `@imagemin-rs/wasm` with its documented in-memory GIF, PNG, and SVG scope.
4. AVIF through the exact optional peer `sharp@0.35.3`; Sharp is not in the
   default install closure.
5. Gifsicle and pngquant remain separate executable packages. Every GPL
   platform tarball contains its matching upstream source, all pinned Cargo
   registry sources where applicable, build scripts, lockfile/configuration,
   and a verified source manifest.
6. AVIF 10/12-bit, an OS-level RSS sandbox, and new codec profiles are outside
   the 1.0 scope.

## Public trial protocol

The trial clock starts only when all 35 packages for one RC are visible on npm
under `next`, the root dependency closure installs, the GitHub Release assets
exist, and all release jobs are green.

The trial RC is `0.1.0-rc.9`. Registry closure and fresh-install verification
completed at **2026-07-30 06:29 +08:00** (`2026-07-29 22:29Z`), which is the
recorded T0. Fourteen consecutive 24-hour periods end at
**2026-08-13 06:29 +08:00**. The public target for 1.0 remains Monday,
2026-08-17, leaving time for the final preflight after the earliest eligible
instant.

Evidence minimum:

- at least three independent consumer installation reports;
- at least two OS families represented;
- at least one report for default installation without Sharp;
- at least one AVIF report after explicit `sharp@0.35.3` installation;
- at least one browser or Web Worker report for `@imagemin-rs/wasm`;
- all reports and defects linked from the public trial issue.

P0 means a security issue, data corruption/loss, or an unusable release.
P1 means a reproducible supported-platform install failure, crash, incorrect
codec result, package/version mismatch, missing license/source material, or
broken WASM deployment. A P0/P1 fix requires a new RC and restarts the 14-day
clock. P2/P3 fixes do not reset the clock unless they change a public contract
or release artifact.

If the evidence minimum is not met when the 14-day period ends, the trial
remains open; stable is not published just to meet the target date.

## Final 1.0 sequence

1. Freeze the last successful RC commit except version and release notes.
2. Run the complete local preflight and tagged eight-platform release matrix.
3. Publish the 35-package `1.0.0` unit through the protected npm environment.
4. Confirm `latest`, tag, GitHub Release, provenance, SBOM, notices, source
   packages, and fresh install all identify `1.0.0`.
5. Keep `next` on the last RC until `latest` verification succeeds, then align
   it with `1.0.0`.

## Post-1.0 roadmap

These items are intentionally non-blocking:

- public cancellation for native tasks and a stronger OS-level resource
  sandbox;
- AVIF 10/12-bit and HDR/color-management contracts;
- broader visual/corrupt-input corpora and longer performance histories;
- additional WASM codecs and streaming APIs;
- a permissive native AVIF profile that does not rely on Sharp;
- further reproducibility work that compares rebuilt sidecar binaries
  byte-for-byte where upstream toolchains permit it.
